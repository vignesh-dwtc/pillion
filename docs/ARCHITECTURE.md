# Architecture

Living document, kept current by the `foundation` subagent. The brief (`docs/BRIEF.md`) is the authority; decisions that deviate from it are in `docs/DECISIONS.md`.

## 1. Layers

```
config/identity.json     product name, application id, service names (single source of truth)
src/core/                PURE TypeScript. No react-native. Fully unit-tested.
  common/                Unsubscribe, Clock, Logger
  protocol/              messages (wire spec), framing, handshake, secure channel, crypto provider
  pairing/               pairing payload: generate, encode, decode, validate
  session/               state machine, reconnect/backoff, testing/ fakes + two-peer simulation
  diagnostics/           ring-buffer log (redacting), stats sampler, report formatter
src/platform/<area>/     interface + native (.ts) + web (.web.ts) implementations
  link/ media/ audio/ service/ permissions/ storage/
src/features/            screens: onboarding, pair, home, ride, settings, diagnostics, debug
src/app/                 navigation, theme, store, composition root
modules/                 local Expo modules (Kotlin): Link, AudioRoute, RideService
specs/                   TypeScript description of each native module's JS surface
plugins/                 Expo config plugins
android/                 generated by `expo prebuild`, committed; never hand-edited
e2e/                     Playwright tests against the web build
scripts/                 cloud-setup.sh, dev relay + static server for web, fetch-doc.sh
```

Dependency direction: `app` -> `features` -> `platform` -> `core`. `core` may import only the platform **interface** files (type-only in practice: `link/LinkTransport`, `media/MediaEngine`, `audio/AudioRoute`, `audio/AudioTunables`, `service/RideService`, `permissions/PermissionService`, `storage/stores`). ESLint enforces this (`import/no-restricted-paths` zones + `no-restricted-imports`).

## 3. Session state machine

`idle -> starting -> linking -> signaling -> connecting -> connected <-> reconnecting -> ended`

- **starting**: permissions, audio route (communication mode, headset), foreground service (must come from a user tap), microphone.
- **linking**: `LinkTransport.open()` (host listens + advertises; guest discovers + connects). One attempt per call; the session owns retry/backoff.
- **signaling**: secure handshake (`core/protocol`), `peer-state` exchange, SDP offer (host) / answer (guest), trickled ICE. Every message carries a `generation`.
- **connecting**: ICE/DTLS until the `MediaSession` reports `connected`.
- **connected**: heartbeats (ping/pong). Loss of heartbeat, link close or media `failed` -> **reconnecting**.
- **reconnecting**: new generation: close the media session, re-open the link with exponential backoff + jitter, renegotiate; repeats for as long as the ride is active, with no user input.
- **ended**: terminal. `end()` is idempotent and releases media, audio route, foreground service and link in a finally path.

Roles: the phone that displays the pairing QR is the **host** (normally the rider's) and owns the link and signaling server; the phone that scans it is the **guest**. The host creates the SDP offer.

## 4. Wire protocol

Spec lives in the header comment of `src/core/protocol/messages.ts`. Summary: `[u32 length][payload]`; plain JSON handshake frames (hello / hello-ack / auth) carrying HMAC proofs of the 32-byte pairing secret, then `[32-byte HMAC tag][JSON]` frames with an implicit per-direction counter, direction keys from HKDF. SDP is MAC'd, which binds the DTLS fingerprint to the pairing: a third party on the same network cannot splice in its own media endpoint. Signaling carries SDP, ICE, heartbeats and peer state (name, muted, headset, battery, interruption).

Pairing payload (QR / pasted string): pair id (16 B), secret (32 B), host display name, Wi-Fi Direct credentials, version. The secret and passphrase are stored only in Keystore-backed storage and never logged or exported.

## 5. Media

`MediaEngine` (whole ride: microphone, mute, tunables) and `MediaSession` (one per negotiation attempt: fresh `RTCPeerConnection`, no ICE servers, host candidates only). Package: `@livekit/react-native-webrtc` (see DECISIONS D-004). Every audio tunable lives in one `AudioTunables` object, editable at runtime from the hidden debug screen (`media` owns how each field is applied: getUserMedia constraints, Opus SDP fmtp, sender parameters). Loopback self-test: two sessions in one process, the receiving side with `sendLocalAudio: false`.

## 6. Native layer (Android)

Local Expo modules in `modules/` (Kotlin), autolinked, merging their own manifest entries, so `expo prebuild --clean` can never delete them. Thin by design:

- `Link`: NSD register/discover, TCP listen/connect, bytes in/out, interface listing; Wi-Fi Direct from M2. Framing/auth stay in TypeScript.
- `AudioRoute`: communication mode and headset selection (`setCommunicationDevice` on API 31+, legacy SCO on 29-30), device-change events, cues through `USAGE_VOICE_COMMUNICATION`, restore on stop, no exclusive audio focus.
- `RideService`: foreground service (microphone + connected-device types), wake and Wi-Fi locks, notification actions, battery.

JS passes names (service type, channel id, strings) at runtime from `config/identity.json`.

## 7. Web verification target

The app also builds for web (React Native Web) so the lead can drive it in headless Chromium. Every platform interface has a `.web.ts` implementation: real browser WebRTC for `MediaEngine`, `WebLinkTransport` over a dev WebSocket relay (`scripts/dev-relay.mjs`) so two browser contexts play host and guest, fakes for `AudioRoute`/`RideService`/`PermissionService`, a web-only dev panel (headset disconnected, link dropped, phone call started), and pairing via the paste-string path. Web proves UI, flows, session logic, signaling and WebRTC negotiation; it proves nothing about Bluetooth, Wi-Fi Direct, the foreground service or background behaviour. `scripts/check-android-bundle.mjs` asserts web-only markers never appear in the Android bundle.

## 8. Renaming the product

Edit `config/identity.json` (display name, Android application ID, URL scheme, pairing prefix, NSD service type), then `npm run prebuild:android` and rebuild. Native code reads no hard-coded names. The application ID is baked into the installed app: after a rename, uninstall the old build and pair again.

## 9. Build, CI and testing

- Jest (Node environment) covers `src/core` and logic-only platform code; UI is verified through the web build + Playwright screenshots.
- Kotlin: JVM unit tests (`./gradlew testDebugUnitTest`) for anything that is not a direct platform call.
- GitHub Actions (`.github/workflows/ci.yml`): typecheck, lint, format check, Jest, web build + Playwright, Android debug build (arm64) with APK artifact. The APK embeds the JS bundle (no Metro needed) so it runs offline on a bike.
- `scripts/cloud-setup.sh` installs the Android SDK in cloud sessions.
